# OSPF Fundamentals

OSPF (Open Shortest Path First) is the dominant open-standard interior gateway protocol — link-state, hierarchical, fast-converging, and vendor-neutral. Every serious network engineer must understand it deeply.

---

## History

OSPF emerged from dissatisfaction with RIP's scalability and convergence characteristics. The IETF formed a working group in 1987 to create a link-state IGP for the rapidly expanding internet.

| Year | Event |
|---|---|
| 1987 | IETF working group begins work on a link-state IGP |
| 1989 | RFC 1131 — OSPF version 1 (experimental) |
| 1991 | RFC 1247 — OSPF version 2, first widely deployed |
| 1994 | RFC 1583 — OSPFv2 update |
| 1998 | **RFC 2328** — OSPFv2 current standard (still in use) |
| 1999 | RFC 2740 — OSPFv3 for IPv6 |
| 2008 | RFC 5340 — OSPFv3 current standard |
| 2016 | RFC 7684, RFC 8362 — OSPFv3 address families (IPv4 + IPv6 in one instance) |

Radia Perlman (who also invented STP) contributed key ideas to OSPF's design. The protocol is named for its core algorithm: Dijkstra's Shortest Path First (SPF).

## Core Concepts

### Link-State Flooding

Each OSPF router generates a **Link State Advertisement (LSA)** describing its directly connected links and their costs. This LSA is **flooded** — sent to every router in the area, forwarded unchanged, acknowledged by each recipient.

Result: every router holds an **identical Link State Database (LSDB)** for its area. Each runs Dijkstra SPF independently to build its routing table.

```
Router A's LSA:
  "I am A. I have links to B (cost 10), C (cost 100), and D (cost 5)."

Router B's LSA:
  "I am B. I have links to A (cost 10) and E (cost 20)."

All routers flood these LSAs to all others → all have the same full picture.
Each runs SPF → each computes its own shortest paths independently.
```

### OSPF Cost Metric

```
Cost = Reference Bandwidth / Interface Bandwidth

Default reference bandwidth: 100 Mbps = 100,000,000 bps

Interface       | Bandwidth    | Default Cost
----------------|--------------|-------------
10 Mbps Ethernet| 10,000,000  | 10
100 Mbps FastEth| 100,000,000 | 1
1 GigEthernet   | 1,000,000,000| 1   ← problem! same as FastEth
10 GigEthernet  | 10G         | 1   ← same!
Serial T1       | 1,544,000   | 64

Fix: always change reference bandwidth to match your fastest links:
  auto-cost reference-bandwidth 1000   ! for 1G networks
  auto-cost reference-bandwidth 10000  ! for 10G networks
  auto-cost reference-bandwidth 100000 ! for 100G networks
  (change on ALL routers in the OSPF domain — must be consistent)
```

## OSPF Hierarchy — Areas

OSPF uses a **two-level hierarchy** to scale. All areas must connect to **Area 0 (backbone area)**.

```
                      ┌───────────────┐
                      │   Area 0      │  ← Backbone; all ABRs connect here
                      │   (Backbone)  │
                      └──┬───────────┬┘
                         │           │
                   ┌─────┘           └──────┐
              ┌────┴──────┐          ┌──────┴───┐
              │  Area 1   │          │  Area 2  │
              │           │          │          │
              └───────────┘          └──────────┘

ABR (Area Border Router) — connects Area 0 to another area; sits in both
ASBR (AS Boundary Router) — connects OSPF domain to another routing domain (BGP, EIGRP, etc.)
IR (Internal Router) — all interfaces in same area
BR (Backbone Router) — at least one interface in Area 0
```

**Why areas?**
1. Limit LSA flooding scope — LSAs don't cross area boundaries (only summaries do via Type 3 LSAs)
2. Limit SPF recalculations — topology change in Area 1 doesn't trigger SPF in Area 2
3. Hide topology details — other areas see only summary routes, not individual links

## LSA Types

| LSA Type | Name | Generated by | Scope | Contents |
|---|---|---|---|---|
| Type 1 | Router LSA | Every router | Within area | Router's links and costs |
| Type 2 | Network LSA | DR on multi-access | Within area | All routers on the segment |
| Type 3 | Summary LSA | ABR | Into backbone/area | Inter-area prefix summary |
| Type 4 | ASBR Summary | ABR | Domain-wide | Location of ASBR |
| Type 5 | AS External | ASBR | Domain-wide (except stubs) | External routes |
| Type 7 | NSSA External | ASBR in NSSA | NSSA area only | External routes in NSSA |

Type 1 and 2 LSAs describe the topology within an area. Type 3, 4, and 5 carry inter-area and external information. Type 7 is Type 5's equivalent inside NSSA areas.

## OSPF Neighbor States

OSPF routers go through a defined state machine when forming an adjacency:

```
DOWN
  │ Start (send Hello)
ATTEMPT (only on NBMA, after explicit neighbor config)
  │ Receive Hello
INIT
  │ Bidirectional Hello (my RID in their Hello)
2-WAY ──────────────────────────────────► STOP HERE for DROTHERs on broadcast networks
  │ Decide to form adjacency (P2P, or DR/BDR relationship)
EXSTART — negotiate Master/Slave, initial DD sequence number
  │
EXCHANGE — exchange Database Description (DD) packets (LSDB summaries)
  │
LOADING — request specific LSAs via LSR; receive via LSU; acknowledge via LSAck
  │
FULL ◄── Desired end state; LSDB synchronized; SPF can run
```

**OSPF packets:**
| Packet | Type | Purpose |
|---|---|---|
| Hello | 1 | Discover neighbors, establish/maintain adjacencies |
| DBD (Database Description) | 2 | Summary of LSDB for EXSTART/EXCHANGE |
| LSR (Link State Request) | 3 | Request specific LSAs during LOADING |
| LSU (Link State Update) | 4 | Carry actual LSAs (flooded) |
| LSAck (Link State Ack) | 5 | Acknowledge received LSAs |

## DR and BDR Election

On multi-access networks (Ethernet), with N routers, a full mesh of adjacencies would require N(N-1)/2 pairs — expensive. OSPF elects a **Designated Router (DR)** and **Backup Designated Router (BDR)** to reduce adjacency count.

```
Multi-access segment with 4 routers: A, B, C, D

Without DR/BDR: 6 full adjacencies (4×3/2)
With DR/BDR:
  All routers form FULL adjacency with DR and BDR only
  DROTHERs (A, B) stay at 2-WAY with each other
  Total FULL adjacencies: 4 (each DROTHER to DR, each DROTHER to BDR)
  + 1 DR-BDR = 5 adjacencies total — scales much better

DR/BDR election:
  1. Highest OSPF priority wins (default 1; range 0-255; 0 = never become DR/BDR)
  2. Tie-break: highest Router ID (highest loopback IP, or highest physical interface IP)
  3. Election is NOT preemptive — once elected, DR stays until it fails or is cleared

Multicast addresses used:
  224.0.0.5 = All OSPF routers (all OSPF routers listen here)
  224.0.0.6 = All OSPF DRs (only DR and BDR listen; DROTHERs send updates here)

Point-to-point links: no DR/BDR election (only two routers, so all form FULL)
  → Set: ip ospf network point-to-point   (skips election, faster convergence)
```

## Hello Parameters — Must Match for Adjacency

OSPF will NOT form a neighbor relationship if these don't match:

| Parameter | Default | Notes |
|---|---|---|
| Hello interval | 10s (broadcast) / 30s (NBMA) | Sent between hellos |
| Dead interval | 40s (broadcast) / 120s (NBMA) | If no hello received, neighbor declared dead |
| Area ID | — | Must be same; can be number or dotted-decimal |
| Authentication | None | Type and key must match |
| Stub area flags | — | Stub/not-stub, NSSA must agree |
| MTU | — | By default, MTU mismatch blocks neighbor formation (ExStart/Exchange stuck) |

```cisco
! Check what's mismatching
Router# show ip ospf neighbor         ! see neighbor state
Router# debug ip ospf adj             ! see why adjacency fails
Router# debug ip ospf hello           ! see hello packets
```

## Router ID

The OSPF Router ID (RID) is a 32-bit number, written like an IP address, that uniquely identifies a router in the OSPF domain.

```
Selection order:
  1. Manually configured (preferred — always do this):
     router-id 10.255.255.1
  2. Highest IP on any loopback interface
  3. Highest IP on any non-loopback interface (at process start time)

Best practice: configure a Loopback interface with a /32 and use it as Router ID.
  → Loopbacks never go down (no physical layer)
  → RID stays stable
  → Loopback is also reachable by OSPF neighbors for management
```

## Cisco IOS OSPF Configuration

```cisco
! Enable OSPF process (process ID is local — not domain-wide)
Router(config)# router ospf 1

! Set Router ID (do this first!)
Router(config-router)# router-id 10.255.255.1

! Advertise networks into OSPF (wildcard mask = inverse of subnet mask)
Router(config-router)# network 10.1.0.0 0.0.255.255 area 0
Router(config-router)# network 192.168.1.0 0.0.0.255 area 1

! Fix reference bandwidth for GigE/10GigE environments
Router(config-router)# auto-cost reference-bandwidth 10000    ! 10 Gbps = cost 1

! Passive interface (no hellos sent/received; network still advertised)
Router(config-router)# passive-interface GigabitEthernet0/1
Router(config-router)# passive-interface default          ! passive by default
Router(config-router)# no passive-interface GigabitEthernet0/0  ! enable on routers

! Advertise default route into OSPF
Router(config-router)# default-information originate         ! only if default route exists
Router(config-router)# default-information originate always  ! always, even without default

! Per-interface configuration (preferred — more explicit than 'network' command)
Router(config)# interface GigabitEthernet0/0
Router(config-if)# ip ospf 1 area 0        ! attach to OSPF process 1, Area 0
Router(config-if)# ip ospf cost 10         ! manually set cost
Router(config-if)# ip ospf priority 100    ! increase priority for DR election
Router(config-if)# ip ospf hello-interval 5       ! change hello timer
Router(config-if)# ip ospf dead-interval 15       ! must be 4× hello or change manually

! Authentication
Router(config-if)# ip ospf authentication message-digest
Router(config-if)# ip ospf message-digest-key 1 md5 MyOSPFPassword

! Point-to-point network type (for P2P links — skips DR/BDR)
Router(config-if)# ip ospf network point-to-point

! Verification
Router# show ip ospf                      ! process information, area counts
Router# show ip ospf neighbor             ! neighbor state table
Router# show ip ospf neighbor detail      ! hello interval, dead timer, etc.
Router# show ip ospf database            ! LSDB contents (all LSA types)
Router# show ip ospf database router     ! Type 1 LSAs only
Router# show ip ospf database summary    ! Type 3 LSAs only
Router# show ip ospf database external   ! Type 5 LSAs
Router# show ip ospf interface           ! per-interface OSPF parameters
Router# show ip ospf interface brief     ! compact overview
Router# show ip route ospf               ! OSPF routes in routing table
Router# show ip ospf border-routers      ! ABR and ASBR in the domain
```

## Stub Area Types

Stub areas limit LSA flooding by restricting external and inter-area LSAs — useful for areas with a single exit point:

| Area Type | Blocks | Receives | Use When |
|---|---|---|---|
| Normal | Nothing | All LSA types | — |
| Stub | Type 5 (external) | Default route instead | Single ABR, few external routes |
| Totally Stubby | Type 3, 4, 5 | Only default route | Single exit, Cisco extension |
| NSSA | Imports Type 7 → converted to Type 5 at ABR | Type 3, Type 7 | Area has ASBR but no Type 5 allowed |
| Totally NSSA | Type 3 also blocked | Only default + Type 7 | Most restrictive NSSA |

```cisco
! Stub area (all routers in area must be configured)
Router(config-router)# area 1 stub

! Totally stubby (Cisco extension — only on ABR)
Router(config-router)# area 1 stub no-summary    ! on ABR only

! NSSA
Router(config-router)# area 2 nssa

! Totally NSSA
Router(config-router)# area 2 nssa no-summary    ! on ABR only
```

## Tips

- Always configure the Router ID manually before starting OSPF — automatic selection can change if interfaces come and go, causing OSPF to reset.
- Change `auto-cost reference-bandwidth` to at least 1000 (for 1G) or 10000 (for 10G) — default of 100 gives GigE a cost of 1, same as 100M.
- Use `passive-interface default` and selectively enable OSPF on router-facing interfaces — prevents accidentally sending hellos out toward hosts.
- On Ethernet segments with only two routers, configure `ip ospf network point-to-point` — eliminates DR/BDR election delay and reaches FULL adjacency faster.
- OSPF MTU mismatch is the most common hidden cause of stuck EXSTART/EXCHANGE states — check `ip ospf mtu-ignore` if you can't fix the MTU.

---

## Summary

- OSPF is a link-state protocol — every router floods LSAs, all build an identical LSDB, each runs Dijkstra SPF independently.
- Cost = reference bandwidth / interface bandwidth — always tune the reference bandwidth to match your fastest links.
- Two-level hierarchy: Area 0 backbone + other areas; ABRs connect them; Type 3 LSAs carry summaries between areas.
- Neighbor adjacency state machine: DOWN → INIT → 2-WAY → EXSTART → EXCHANGE → LOADING → FULL.
- DR/BDR election on Ethernet reduces full mesh adjacency count; P2P links skip election.
- Hello/Dead interval, area ID, stub flags, and authentication must match for adjacency to form.
